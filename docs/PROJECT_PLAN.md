# 项目计划 v0.2

日期：2026-10-24。状态：首版本应用已实现；本轮验证与剩余差异见 [开发验收记录](DEVELOPMENT_REPORT.md)。

## 1. 项目目标

开发一个 ESP32 版 [Learn Arduino](https://learn-arduino-red.vercel.app/)。

- 页面和交互：按原站复刻。
- 开发板和电路：替换为 ESP32-DevKitC V4 / ESP32-WROOM-32E。
- 课程内容：按 ESP32 的能力组织，保持 16 张课程卡片及同一套课程展示方式。

“交互相同”与“课程相同”分开处理。原站是操作与视觉的参照，乐鑫资料是 ESP32 技术内容的依据。

不再以提高课程考核强度或重做学习流程作为本项目目标。独立搭建能力、学习效果试验和自动评分不作为复刻验收项。

## 2. 允许变化与保持一致的内容

| 内容 | 决定 |
| --- | --- |
| 标题和板型标识 | 改为 ESP32 入门及所选板型 |
| 开发板模型、丝印和热点 | 按 ESP32 板型重做 |
| 引脚和接线 | 按 ESP32 实际外设能力适配 |
| 示例代码、量程、规格和说明 | 按 Arduino-ESP32 编写 |
| 16 课主题 | 贴合 ESP32，不强制对应原站 Uno 的主题 |
| 整体视觉、布局和面板层级 | 对照原站保持一致，适应原站同类响应式变化 |
| 课程选择、元件选择、场景操作 | 对照原站保持一致 |
| 概览/引脚图/示例/规格 | 名称、位置和切换方式保持一致 |
| 元件参数、代码数值联动 | 与原站相同入口、反馈及实时更新方式 |
| 运行、停止和串口面板 | 保持原站流程，板型文本替换为 ESP32 |
| 进度 | 按原站运行后的完成标记记录，首次完成从 0/16 增加，不新增任务门槛 |
| 设置、语言入口及记忆 | 按原站交互复刻 |

不增加：预测页面、强制顺序闯关、变化题、评分、证据系统、AI 助教、账户、云同步、工程下载按钮、任意拖线搭建、任意代码编译或浏览器烧录。

代码复制保留。开发者仍需要维护可编译的同课固件作为正确性依据，但不把额外固件工作流加入网站界面。

## 3. 原站式使用流程

进入页面 → 选择课程 → 观察和操作 3D 场景 → 点击元件或代码数值修改参数 → 查看四个页签 → 运行/停止 → 查看串口和场景反馈。

上述动作按原站允许的顺序自由操作，不插入额外学习步骤。运行记录与参数在刷新后恢复；完成进度不代表真机测试或掌握程度。

## 4. 课程范围

共 16 课。以下分组仅用于文档说明，不增加阶段菜单或阶段解锁：

| 课程 | 内容 |
| --- | --- |
| 01—04 | 认识 ESP32、LED、串口、按钮 |
| 05—08 | ADC 旋钮、PWM/RGB、温度、非阻塞控制 |
| 09—12 | OLED、蜂鸣器、舵机、状态机告警 |
| 13—16 | Wi-Fi、HTTP、网页控制、联网温度监测与告警 |

每课仍使用原站四个页签，内容与参数说明见 [ESP32 课程内容](CURRICULUM.md)。没有试卷、任务通过页或单独的考核面板。

## 5. 运行机制

沿用原站的参数化教学模拟：课程标识选择对应行为函数，参数和元件输入驱动场景、代码和日志。

保留原站开始运行时的过渡节奏和反馈位置，在已有状态文本中使用“模拟编译”“模拟上传至 ESP32”等表述，避免把浏览器演示写成真实烧录；不为此另建弹窗或流程。

Wi-Fi/HTTP 章节同样在既有场景、元件检查器、代码和串口区域表达连接与请求过程，不要求学习者进入新设计的实验工作台。实际 Wi-Fi、固件和设备网页的操作说明放在“示例”页签。

## 7. 基本验收

1. 类型检查、生产构建各一次。
2. 按 [交互复刻清单](INTERACTION_SPEC.md) 核对入口、状态、反馈、快捷键和记忆方式。
3. 在原站和复刻站使用相同窗口尺寸，对照桌面和手机的默认、检查器、运行、原理图等代表状态。
4. LED、按钮、ADC/PWM 各走通一条完整路径，确认场景、参数、代码、日志和进度一致。
5. 其余课程各检查核心操作及默认运行一次，不对参数取值进行穷举。
6. 对课程固件默认配置分别编译，并检查板型、电压、引脚、外设 API 和同课行为；编译不等同于真机测试。
7. 手机核对布局和基本触摸操作；全量截图回归、跨浏览器矩阵或大批量测试前先对齐范围。

视觉差异分为两类：ESP32 和课程内容带来的必要变化；导航、面板、控件、动画和布局的复刻偏差。后者按原站修正，不以课程更专业为由接受差异。
