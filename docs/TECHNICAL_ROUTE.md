日期：2026-10-24。基线：原站交互复刻，课程与开发板适配 ESP32。应用已按本路线实现，验证状态见 [开发验收记录](DEVELOPMENT_REPORT.md)。

| 层次 | 选择 |

| 3D | Three.js、WebGLRenderer、正交相机、拾取和程序化器件模型 |

## 2. 参考站机制及复刻依据

本次观察的公开构建使用 Vite 和 Three.js；课程描述包括页签内容、器件、参数、代码及实验标识。运行按标识选择行为函数，实时读取当前参数。

原站运行路径中的编译/上传过程是过渡演示，之后启动课程模型。复刻站保留相同反馈位置与节奏，在文字中标注“模拟”，并把目标板型改为 ESP32。

完整操作要求见 [交互复刻清单](INTERACTION_SPEC.md)。原站资料不是本项目已获授权的代码库，应用和模型独立实现。

## 4. 运行与联动链路

~~~mermaid
flowchart TB
    L[课程定义] --> U[卡片、四页签、检查器]
    L --> S[3D 与 SVG 原理图]
    L --> C[C++ 模板]
    P[检查器与代码数值调参] --> V[当前参数]
    V --> C
    V --> M[当前课程行为模型]
    I[器件操作与环境输入] --> M
    M --> S
    M --> O[读数、串口、声音、代码区域提示]
    R[运行成功进入模拟状态] --> D[首次记录本课完成]
~~~

1. 选择课程后，场景、热点、元件列表、四个页签和代码一起更新。
2. 点击代码数值打开对应检查器，检查器修改值后同步代码和场景。
3. 运行时实时读取参数，不统一强制停止或重启。模式切换所需的局部清理由各课模型定义。
4. 点击运行后采用原站同类启动过渡。普通动画模式参照当前观察构建的两个约 600 ms 阶段；减弱动画设置同步缩短，M1 再核对具体反馈。
5. 模型进入运行后更新串口和输出，并将当前课 ID 加入完成集合；重复运行不重复计数。
6. 停止或切章结束旧模型与音频，旧回调不得写入新场景；每课参数独立保存。
7. 相机、弹层、页签和串口的交互不改变实验逻辑，除非原站该操作本身带有运行切换。

相机与动画用 requestAnimationFrame，模型按模拟时间计算。代码高亮是教学映射，不宣称执行了任意 C++。

- 联网课程用开发板、路由器和浏览器对象表达数据关系；参数和操作继续放在检查器，信息放在原有页签和串口。

## 6. ESP32 适配

| 项目 | 约束 |
| --- | --- |
| GPIO | 使用 GPIO 编号；34/35 为 ADC1 输入；34—39 不能输出或启用内部上下拉 |
| 保留引脚 | 不占 GPIO6—11、串口1/3及启动配置脚0/2/5/12/15作普通实验输出 |
| LED | GPIO23 外接 LED，不把板上电源灯当可控 LED；限流按3.3 V估算 |
| 按钮 | GPIO27 对地、INPUT_PULLUP，按下为 LOW |
| ADC | 12 位原始值；说明衰减、量程及饱和，不沿用 Uno 的 10 位/5 V换算 |
| 温度 | TMP36→GPIO35，真机用校准毫伏值；温度=(mV−500)/10 |
| PWM | Arduino-ESP32 3.x ledcAttach/Write/WriteTone，不维护旧API分支 |
| I²C | SDA21/SCL22、3.3 V供电与上拉；OLED依赖在引入时锁定 |
| 舵机 | GPIO18信号、单独稳压5 V供舵机、共地，外部电源不接入板供电脚 |
| 综合课 | GPIO35/27/23/25/21/22不冲突，ADC1避免ADC2与Wi-Fi共用问题 |

GPIO18在RGB和舵机两个独立场景复用，不在同一电路叠接。LEDC外设按实际频率/分辨率初始化，不能假定不同通道就必有不同定时器。

模型的简化关系、量程与实物误差在规格页签说明。TypeScript 与 C++ 是两种实现；共享参数不证明语义等价，必须对照课程给定的行为检查。

## 7. 告警课程统一规则

状态用于第12和16课，不形成新增考核流程。T为温度、H为阈值、press为本轮稳定按下事件：

| 原状态 | 条件（按表内优先级） | 下一状态 | 输出 |
| --- | --- | --- | --- |
| 任意 | T < H | NORMAL | 灯灭、静音 |
| NORMAL | T >= H，无论同轮是否有press | ALARM | 灯亮、发声 |
| ALARM | T >= H且press | ACK | 灯亮、静音 |
| ALARM | T >= H且无press | ALARM | 灯亮、发声 |
| ACK | T >= H | ACK | 灯亮、静音 |

先采集输入和稳定按键事件，再应用合法的运行时阈值修改，最后按原状态查表。NORMAL刚进入ALARM的同轮按键不直接确认，需要后续新的稳定按下事件。网页返回本轮更新后的同一状态。

阈值是10—50 °C的整数；网络配置接口校验失败不改变阈值。此规则只确定ESP32课程内容，不改变原站的通用交互。

## 8. 联网模拟与真机说明

站内：预设课堂网络 → 课程模型中的连接状态 → 模拟HTTP请求 → 设备模型路由 → 场景/日志反馈。它不访问电脑真实网络设置，也不假装已连接用户硬件。

真机：示例页签说明本地填写Wi-Fi配置、编译烧录、串口读取IP、同一局域网直接打开ESP32网页。设备网页与API同源；教学站不跨域调用HTTP硬件。

| 课程 | 接口 | 内容 |
| --- | --- | --- |
| 14—16 | GET /api/state | JSON设备状态 |
| 15—16 | GET / | ESP32提供的网页 |
| 15 | POST /api/led | 表单value=0/1；不合法为400 |
| 16 | POST /api/config | 表单threshold=10—50整数；不合法为400 |
| 14—16 | 未知路径 | 404 |

第16课状态字段为temperatureC、thresholdC、alarmState、led、buzzer、networkConnected。站内协议入口在浏览器对象检查器，响应在既有日志/读数区，不新增HTTP实验控制台。
