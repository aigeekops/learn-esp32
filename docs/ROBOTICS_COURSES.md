# ESP32 机器人课程：第 17–25 课

这组课程把已有的 GPIO、PWM、定时和联网基础接到机器人的感知、执行、反馈与通信。它是整个项目的主干，不是附加章节：前 16 课是零件库，这里把它们装成一台可被指令指挥、能闭环、会安全停车的机器人。对外指令采用 ROS 2 的 Twist 语义（m/s、rad/s），由固件换算成左右轮目标。0→1 的分段验收见 [README 的定位一节](../README.md#定位)。每课继续使用可点击的 3D 元件、原理图、参数、串口读数和 Arduino C++ 示例。场景中的电脑、手机和无线对端是教学模型；网页不会连接真实串口或蓝牙设备。

| 课次 | ID | 操作与学习目标 |
| --- | --- | --- |
| 17 | `distance` | 移动障碍物，比较距离、回波时长和无回波状态 |
| 18 | `motor` | 调节有符号 PWM，体验正转、滑行停止、反转和负载影响 |
| 19 | `encoder` | 读取带方向计数，以 CPR 和采样时间换算 RPM |
| 20 | `speed` | 比较开环与 PI 闭环，改变负载及 Kp、Ki |
| 21 | `differential` | 调整线速度和角速度，观察两轮目标与转弯轨迹 |
| 22 | `uart` | 发送带换行的速度指令，区分确认、状态与超时 |
| 23 | `ble` | （选做）通过 GATT Write 下发指令、Notify 读取实测轮速 |
| 24 | `espnow` | （选做）同信道双 ESP32 交换带序号的数据包和状态回包 |
| 25 | `robot` | 组合 UART、双轮闭环、超声波停车与里程计位姿 |

第 23、24 课是同一套 `TWIST` 指令契约的两种无线载体，任选其一即可；第 25 课只用 UART，不依赖这两课。

## 接线约定

开发板为 ESP32-DevKitC V4 / ESP32-WROOM-32E。课堂模型使用独立稳压 5 V 给电机驱动 VM 和 HC-SR04 供电，TB6612 逻辑 VCC、编码器逻辑使用 3.3 V，所有设备共地。实际电机电源需匹配所选电机，且堵转电流不能超过驱动器额定值。GPIO 不直接驱动电机。

| ESP32 引脚 / 端点 | 连接 |
| --- | --- |
| GPIO25 / 18 / 19 | TB6612 PWM_A / AIN1 / AIN2 |
| GPIO26 / 23 / 27 | TB6612 PWM_B / BIN1 / BIN2（双轮课程） |
| GPIO4 | TB6612 STBY |
| TB6612 AO1 / AO2 | 左电机 M1 / M2 |
| TB6612 BO1 / BO2 | 右电机 M1 / M2 |
| GPIO32 / 33 | 左编码器 A / B |
| GPIO34 / 35 | 右编码器 A / B |
| GPIO13 | HC-SR04 TRIG |
| GPIO14 | ECHO 分压中点，不能直接接 5 V ECHO |
| GPIO16 / 17 | UART2 RX / TX，分别接上位机 TX / RX |
| GPIO23 | 第 17 课的 330 Ω 串联 LED；双轮课程中用于 BIN1 |

本课指定编码器输出为 **3.3 V 推挽逻辑**。GPIO34/35 没有内部上拉；若更换为开集电极输出的编码器，需按器件要求配置到 3.3 V 的外部上拉。编码器正反方向需校准，确保车轮前进时计数增加。

HC-SR04 ECHO 接线为：`ECHO → 2.2 kΩ → GPIO14 → 3.3 kΩ → GND`。5 V 回波经过分压后约为 `5 × 3.3 / (2.2 + 3.3) = 3.0 V`。原理图中的两只电阻均可点击查看，场景也保留独立连接端点。

面包板配电采用独立插孔：公共地使用第 26、25 行左半排并以跳线桥接；3.3 V 使用第 27 行右半排；5 V 使用第 24 行右半排。这里的行号是模型从 0 开始的编号。每根导线占一个孔，同排五孔的内部导通用于分配电源，不把多个插头叠在同一孔。

### 从实验台到机器人：一次性迁移

第 1–16 课是面包板实验台：LED、按钮、电位器、温度、蜂鸣器、RGB、舵机、土壤和钢琴 8 键占用了上表中的 13 个引脚，只有 OLED 的 21/22 是独占的。ESP32-DevKitC V4 一共 24 个可用 GPIO，而机器人一项就固定占 15 个——**一块板带完全部 25 课在物理上不成立**，所以课程显式分两段接线。

进入第 17 课前按 [引脚预算表](PIN_MAP.md) 的迁移清单收线：拆掉 LED 23、按钮 27、电位器 34、温度 35、蜂鸣器 25、RGB、舵机 18、土壤 34 与钢琴 8 键，保留 OLED 21/22；再按课次逐步接入超声波 13/14 → TB6612 25/18/19/4 → 编码器 32/33 → 右轮 26/23/27 与右编码器 34/35 → UART2 16/17，每接一组烧一次固件再调。

想用一块板走到底，引脚预算表给了三个方案：默认两段式、加一块 I²C IO 扩展器（MCP23017 / TCA9555）、或换 GPIO 更多的板型（ESP32-S3 / C3 / P4）。

## 电机、编码器和闭环

教学电机空载最高转速为 180 RPM，以约 0.25 s 时间常数接近当前 PWM 和负载决定的速度。增加负载会降低可达转速；超过电机能力的目标不会凭空实现。PWM 为 0 表示撤去驱动、滑行停止，机械惯性仍存在。

模型的真实编码器固定为 **360 counts/rev**；课件中的 CPR 参数代表程序采用的标定值。把软件 CPR 从 360 改为 720，会使同一运动的报告转速约减半。固件按 A 相上升沿计数，B 相判断方向；CPR 必须包含减速比和该计数方式，不能直接照抄其他电机的参数。

每 100 ms 读取计数差，计算 `RPM = Δcount × 60 / (CPR × Δt秒)`。PI 使用目标与编码器测量值的误差，输出限幅至 −255…255；误差继续推动输出饱和时暂停积分。目标为 0 时清除积分和驱动输出。目标、实测和 PWM 历史最多保留 60 个采样点。

差速目标使用 `vL = v − ωL/2`、`vR = v + ωL/2`，再用轮半径转换为 RPM。两轮超过 150 RPM 时等比缩小目标，保持曲率。场景轨迹由编码器测量值积分，用于说明差速运动与里程计，不包含轮胎打滑、摩擦死区、电池压降、碰撞动力学或外部定位。PI 参数和电机模型未经过真机辨识。第 21 课给出里程计算法，第 25 课把它接到整机上：每 100 ms 用实测轮速累积 X、Y 与航向，STATE 行带 `POSE=` 字段，读数面板同步显示位姿。

## 指令与停止规则

对外接口用 ROS 2 的 Twist 语义：`TWIST,<v>,<w>`，`v` 是线速度（m/s，±0.25），`w` 是偏航角速度（rad/s，±2）；`STOP` 立即停车。固件按轮径 `r`、轮距 `L` 换算 `vL = v − ωL/2`、`vR = v + ωL/2`，再换成左右轮 RPM；超过 150 RPM 时两轮等比缩放，保持曲率。`SET,<leftRPM>,<rightRPM>` 只保留给台架调试，不属于对外契约。

UART 帧以换行结束，BLE Write 可带末尾 CR/LF。错误、越界、非有限值和超长帧不会改变目标，也不会刷新命令时间。真实 ROS 2 接入由桥接节点负责：Jazzy 用 `geometry_msgs/Twist`，Kilted 及之后默认 `TwistStamped`——话题名不变，类型不匹配会静默不动。

所有通信课程开始时保持停止。收到合法命令后才驱动；**1000 ms 没有合法新命令就撤去驱动**。网页的“发送一次”发送单条指令；“按住持续发送”每 250 ms 发送一次，松开后最后一条指令满 1000 ms 时停车。真机持续遥控也应周期发送，例如每 200 ms 一次。

BLE 断开连接会清除目标，重连后需要新命令。UART 真机无法仅凭电线拔出立即识别断连，依靠 1000 ms 指令超时停车。ESP-NOW 信道不匹配导致无法接收新包，旧命令也会按超时规则失效。模型也区分这些语义：BLE 断连立即停机；UART 和 ESP-NOW 失联后按命令超时停车。

第 25 课中，距离 **小于或等于** 停车阈值，或测距无效时，两轮停止并清除目标；前进、后退、旋转采用同一规则。移开障碍物后仍需重新发送合法命令。超声波每 100 ms 触发，ECHO 边沿由中断计时，25 ms 无回波判无效；没有回波不能当作 0 cm 或通道畅通。这是停车示例，不是避障规划或自主导航。

## BLE：写入和通知

手机作为 GATT 客户端连接设备 **ESP32 Robot**：

| 用途 | UUID |
| --- | --- |
| 服务 | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| Write 指令 | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` |
| Notify 状态 | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` |

向 Write 特征写入 `TWIST,0.15,0`；订阅 Notify 后，每 200 ms 收到四个有符号整数 RPM：`目标左,目标右,实测左,实测右`，例如 `60,60,58,59`。课程设计范围内该 CSV 可装入默认 ATT MTU 23 对应的 20 字节通知负载；状态通知不包含 UART 的 `STATE` 前缀与 PWM 字段。回调只校验并缓存指令，主循环执行控制。本课使用 BLE GATT，不使用经典蓝牙 SPP。

## ESP-NOW：两块板分别烧录

1. 导出默认接收端 `output/sketches/espnow/espnow.ino` 和额外发送端 `output/sketches/espnow-sender/espnow-sender.ino`；课件中的“示例代码角色”也可切换这两份代码。
2. 两块板均使用 Wi-Fi STA 模式，串口打印自己的 STA MAC。分别把**另一块板**的地址填入各自的 `PEER_MAC`；全 0 占位值不会开始发送。
3. 两端的 `RADIO_CHANNEL` 必须一致，课堂默认 6。无需连接路由器。
4. 在发送端 USB 串口以换行发送 `TWIST,0.15,0` 或 `STOP`。持续运动需要周期发送；接收端仍执行 1000 ms 指令超时。
5. 接收端检查来源 MAC、包长、标识、版本、序号与速度范围，接受有效新命令后回传目标 v、ω 与编码器实测轮速。重复或倒序包不刷新命令。

发送回调说明链路投递结果；**状态回包**才说明对端应用已处理命令。双方代码使用同一数据包结构（当前 version 2：v 用 mm/s、ω 用 mrad/s、实测用 RPM），不能混用不同版本；示例未启用 ESP-NOW 加密。页面演示信道匹配、发收计数与状态回报，不模拟实际射频传播和所有底层报文。

## 运行与验证边界

固件基线沿用 Arduino-ESP32 3.3.12，模型与固件均使用项目已有导出、构建及测试流程。编译成功只能证明工具链接受源码；课程当前不宣称电机、手机 BLE 或双板 ESP-NOW 已通过真机联调。各次实际执行的验证以带日期的验收报告为准。
